GitHub review tracer

TL;DR — Debug from left to right: installation → webhook → gate → model → schema → review API. Each boundary has one owner and one observable output.

Trace

BoundaryOwnerObservable output

Decision table

ConditionResult
Action is not openedReturn null; no model turn
PR is a draftReturn null; no model turn
Safety rating ≥ 3Summary review; force comments: []
Safety rating < 3Summary plus valid changed-line findings
Conversation is not a PRPost the normal message to its thread

Formal review payload

POST /repos/{owner}/{repo}/pulls/{number}/reviews
{
  "event": "COMMENT",
  "body": "## Safety Rating: …",
  "commit_id": "{headSha}",
  "comments": [
    { "path": "src/x.ts", "line": 42, "side": "RIGHT", "body": "…" }
  ]
}

COMMENT is advisory. Inline locations use RIGHT for new/context lines and LEFT for deleted lines. Source: GitHub Reviews API.

Debug in this order

  1. Reach: is the App installed for this repository?
  2. Ingress: did GitHub send a signed pull_request webhook?
  3. Admission: was it exactly opened and non-draft?
  4. Generation: did the turn complete with a message?
  5. Validation: does the message parse against reviewSchema?
  6. Delivery: did GitHub accept the review endpoint and anchors?
Rule
Stop at the first missing output. Inspecting a downstream boundary before its input exists produces misleading symptoms.
