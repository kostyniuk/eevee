# Mission: Build and understand the eevee review agent

## Why
Ship each eevee implementation phase while learning its architecture, so the agent can be debugged and extended deliberately instead of becoming a black box.

## Success looks like
- Trace a GitHub event from installation and webhook ingress to the published review.
- Explain why each architectural boundary exists and change it safely.
- Design, verify, and ship later phases with an explicit mental model of the system.

## Constraints
- Lessons follow the repository's real implementation phases and stay short.
- Lesson and reference artifacts use the warm ivory, slate, clay, oat, and olive visual system.
- Do not create commits, merges, or pull requests until explicitly requested.

## Out of scope
- Generic platform tutorials that do not help build eevee.
- Teaching later features before their implementation phase begins.
